系统安全 / 信息安全 System & Cyber Security

主线：资产 → 威胁 → 攻击面 → 防护 ｜ 标准：ISO/SAE 21434（网络安全工程）、UN R155 / R156（法规）

1. 什么是汽车信息安全

随着网联化（蜂窝/V2X）、OTA 升级、车载以太网普及，汽车从"封闭机械"变成"联网终端"，攻击面急剧扩大。汽车信息安全（常称 Cyber Security）保护的是机密性、完整性、可用性（CIA），防范的是人为蓄意攻击——这与功能安全（管系统自己出错）正好互补。

协同关系：一次成功的网络攻击（如伪造制动指令）会直接引发安全事故。行业共识是"security is a prerequisite for safety"——没有安全，功能安全无从谈起。ISO 26262 与 ISO/SAE 21434 在项目层面要联合裁剪、共享危害/威胁分析。

2. 标准与法规

文件性质要点
ISO/SAE 21434国际标准道路车辆网络安全工程流程：从概念→开发→生产→运维全生命周期的网络安全活动
UN R155联合国法规CSMS（网络安全管理体系）强制要求，车型准入前提
UN R156联合国法规SUMS（软件更新管理体系）+ OTA 合规

3. TARA：威胁分析与风险评估

TARA 是 21434 的核心活动，对应功能安全里的 HARA，串法如下：

  1. 资产识别：列出需要保护的东西（密钥、CAN 报文、固件、用户隐私数据）。
  2. 威胁建模：用 STRIDE 系统枚举威胁——Spoofing（伪造）、Tampering（篡改）、Repudiation（抵赖）、Information Disclosure（泄露）、Denial of Service（拒绝服务）、Elevation of Privilege（提权）。
  3. 攻击路径 / 攻击树：从攻击者能力出发，画"如何达成危害"的路径。
  4. 影响评级 & 攻击可行性：评估安全/隐私影响与攻击难度。
  5. 风险处置：规避 / 缓解 / 转移 / 接受，导出网络安全目标与需求。
与 HARA 对照记忆：TARA 用 STRIDE+影响评级定风险，HARA 用 S/E/C 定 ASIL。一个是"防人"，一个是"防失效"，但都是"先分析、再定级、再出安全/安全需求"的同一种工程思维。

4. 常见攻击面

  • 车载网络：传统 CAN/CAN FD 无身份认证、无加密，可伪造报文（如伪造制动/转向指令）——典型风险。
  • 车载以太网：面向服务架构（SOA）带来更多远程可达接口。
  • OTA / 固件：刷写通道若未签名校验，可被植入恶意固件。
  • 无线入口：蓝牙、Wi-Fi、蜂窝、钥匙（RFID 中继攻击）。
  • 传感器：激光雷达/摄像头可被物理对抗样本欺骗（见第 6 节）。
  • ECU 固件：逆向提取密钥、调试接口未锁。

5. 防护手段

手段作用
SecOC（Secure Onboard Communication）给 CAN 报文加 MAC + 新鲜值，防伪造/重放
HSM / Evita 架构硬件安全模块，密钥不出芯片，做加解密与签名
安全启动（Secure Boot）逐级验签，拒绝未授权固件
固件签名 / OTA 验签保证刷入的是厂商可信镜像
IDS（入侵检测系统）监测总线/网络异常行为
密钥管理 / PKI证书生命周期、吊销、隔离

6. 深度学习与汽车信息安全（重点交叉区）

这一节把你的算法/感知背景接到安全攻击与防御两端——既是威胁来源，也是防御工具。

6.1 威胁：对抗样本攻击感知系统

深度学习模型对输入扰动敏感，攻击者可在物理世界制造对抗效果：

  • FGSM（快速梯度符号）：沿损失梯度符号方向加一步小扰动，成本低、易实现。
  • PGD（投影梯度下降）：FGSM 的多步迭代版，更强（"一阶最强"攻击），常作鲁棒性基准。
  • 物理对抗补丁 / 贴纸：贴在路牌或车上，使目标检测漏检（如"停止标志"被识别为其他），直接转化为安全事故。
与功能安全呼应：同一个对抗补丁，在信息安全视角是"蓄意攻击"，在功能安全/SOTIF视角是"性能不足导致危害"。两页对照，能讲清 safety 与 security 的协同。

6.3 用 DL 做安全工具

反过来，深度学习也是强大的安全手段：

  • CAN 总线入侵检测：用序列模型学习正常报文时序，检测伪造/异常帧。
  • 日志 / 流量异常检测：无监督异常检测发现未知攻击模式。
  • 固件/恶意流量分类：端到端分类识别威胁。

7. 学习路线速查

  1. 先建立 CIA + 攻击面概念，读 UN R155 概要。
  2. 掌握 TARA 流程与 STRIDE，能对着一个 ECU 画威胁树。
  3. 理解 SecOC / HSM / 安全启动的"为什么"，不必死记命令。
  4. 把对抗样本（FGSM/PGD）作为 DL 与安全的结合点，亲手跑一遍小实验。
  5. 最后回到"security → safety"协同，和功能安全页打通。
